# XG5000 버블 에이전트 Office Hours 정리

**Date:** 2026-03-28  
**Skill:** `gstack-office-hours`  
**Branch:** `master`

## 한 줄 정의

이 제품은 `XG5000 초보자를 위한 상위 오버레이형 실행 보조 에이전트`다.  
평소에는 작은 원형 버블로 떠 있고, 클릭하면 패널이 열리며, 현재 화면 설명, 문제 원인 추정, 다음 클릭 안내, 승인 후 메뉴/입력 실행까지 도와준다.

## 이 제품이 진짜 해결하는 문제

사용자는 PLC 전문가가 아니다.  
문제는 "XG5000를 쓴다"가 아니라, `지금 보고 있는 화면이 뭔지 모르고`, `무엇부터 눌러야 할지 모르고`, `실수했을 때 왜 안 되는지 감이 안 온다`는 점이다.

즉 사용자가 사려는 것은 다음이다.

- 화면을 읽어주는 튜터
- 다음 클릭을 알려주는 코치
- 잘못된 설정과 배선 원인을 찾아주는 문제 해결사
- 필요하면 일부 반복 UI 작업을 대신 해주는 실행 도우미

## 상태 그대로의 경쟁 상대

사용자가 지금 대신 쓰는 것은 사실상 이것들이다.

- XG5000 매뉴얼 PDF를 뒤적임
- 유튜브/블로그 검색
- 커뮤니티 질문
- 숙련자에게 화면 사진을 보내서 물어봄
- 아무 버튼이나 눌러 보다가 꼬임

이 제품의 가치는 `툴을 새로 만드는 것`이 아니라, `숙련자에게 물어보는 시간을 화면 위로 끌어오는 것`이다.

## 가장 아픈 순간

사용자가 가장 답답한 순간은 아래 네 가지다.

1. 지금 화면이 무엇인지 모르겠다.  
2. 통신/접속/파라미터 화면에서 어디를 봐야 할지 모르겠다.  
3. 에러 코드나 프로그램 검사 결과가 무슨 뜻인지 모르겠다.  
4. 입력이 안 들어오거나 배선이 이상한데 원인을 못 좁히겠다.

이 네 가지를 풀지 못하면, 고급 기능이 많아도 제품은 쓸모가 없다.

## 좁은 시작점, narrowest wedge

가장 먼저 완성해야 하는 좁은 쐐기는 이거다.

**"XG5000 화면을 보고, 지금 상태를 설명하고, 다음에 무엇을 눌러야 하는지 알려주고, 승인 후 메뉴/입력까지 대신 해주는 것."**

여기서 배선/회로는 2번째 축이다. 중요하지만 첫 성공 경험은 `XG5000 화면 코치`에서 나와야 한다.

## 무엇을 절대 하면 안 되나

첫 릴리스에서 피해야 할 것들이다.

- PLC 쓰기/다운로드 자동화
- 강제 출력
- 모드 전환
- 래더 그래픽 직접 편집
- 너무 큰 대시보드형 콘솔 UX

이건 제품을 무겁게 만들고, 실패했을 때 위험이 너무 크다.

## 제품 포지셔닝

이 제품은 PLC IDE가 아니다.  
PLC 운영 콘솔도 아니다.

이 제품은 아래 포지션이 맞다.

**"XG5000 위에서 동작하는 초보자용 AI 실무 튜터 + 승인형 UI 실행 에이전트"**

## 첫 릴리스에서 사용자가 느껴야 하는 것

첫 30초 안에 사용자는 이 4가지를 이해해야 한다.

- 이 아이콘은 XG5000 화면을 읽어준다
- 내가 막힌 이유를 같이 좁혀준다
- 다음 클릭을 알려준다
- 승인하면 일부 작업을 대신 해준다

이 4개가 안 보이면 제품 메시지가 실패한 것이다.

## 추천 제품 흐름

### Flow 1. 화면 설명

- 버블 클릭
- "지금 화면 설명"
- 현재 XG5000 화면 해석
- 현재 상태 / 다음 클릭 / 주의점 표시

### Flow 2. 문제 원인 찾기

- 버블 클릭
- 증상 입력
- 최신 캡처와 문맥 결합
- 가능성 높은 원인 3개와 확인 순서 제시

### Flow 3. 승인 후 실행

- AI가 메뉴 열기, 대화상자 이동, 텍스트 입력 같은 액션 제안
- 사용자 승인
- 한 단계 실행
- 결과 캡처 후 다음 단계 제안

### Flow 4. 배선/회로 진단

- 이미지 또는 구조화 입력
- 공통선, NO/NC, sink/source, 전압 레벨 불일치 점검
- 가장 가능성 높은 원인과 체크리스트 출력

## 오히려 줄여야 하는 것

지금 코드베이스에는 다음이 아직 남아 있다.

- PLC 운영 콘솔 성격의 화면
- OPC UA, PKI, preset 같은 고급 운영 기능
- 다중 화면형 정보 구조

이건 `Advanced` 뒤로 보내는 게 맞다.  
기본 제품 경험은 버블 에이전트 하나로 설명돼야 한다.

## 제품 판단

이 아이디어는 괜찮다. 문제도 진짜다.  
다만 실패하는 방식도 명확하다.

- UI가 크고 복잡하면 망한다
- 버블이 안 보이거나 클릭이 불안하면 망한다
- "뭘 도와주는지" 첫 화면에서 안 보이면 망한다
- 실행 에이전트라 해놓고 실제로는 못 누르면 신뢰를 잃는다

반대로 이것만 되면 초보자에게는 꽤 강하다.

- XG5000 화면 인식
- 다음 클릭 안내
- 승인형 UI 실행
- 에러/배선 원인 좁히기

## 추천 결론

1. 제품 핵심은 `버블형 화면 코치 + 승인형 실행 에이전트`로 고정  
2. 첫 성공 경험은 `현재 화면 설명`과 `다음 클릭 안내`에서 만든다  
3. 배선/회로 진단은 두 번째 축으로 붙인다  
4. 고급 PLC 운영 기능은 기본 UX에서 숨긴다  
5. "IDE처럼 다 해주는 앱"이 아니라 "초보자의 숙련자 대리인"으로 포지셔닝한다
