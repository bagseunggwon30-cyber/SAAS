# B안 고도화 로드맵

## 목표

XG5000 내부 플러그인 대신, 별도 데스크톱 보조앱이 다음 3가지를 최대한 자동화하도록 고도화한다.

- XG5000 프로젝트/변수/코멘트 변경 사항을 빠르게 반영한다.
- XG5000 작업 중 바로 꺼내 쓸 수 있는 UX를 제공한다.
- PLC 실시간 상태와 프로젝트 스냅샷을 함께 보여준다.

핵심 원칙은 `내장형처럼 느껴지는 외부 보조앱`이다.  
즉, 프로세스 통합이 아니라 `동기화`, `항상 위`, `단축키`, `파일 감시`, `세션 복원`으로 사용감을 끌어올린다.

## 현재 기준

- 앱은 Electron + React + TypeScript + SQLite 기반으로 동작한다.
- PLC 연동은 현재 `SimulatedPlcAdapter` 기준이다.
- 프로젝트 import는 파일 선택 후 감사 로그와 컨텍스트 반영까지 구현되어 있다.
- 부트스트랩은 `app.bootstrap` 단일 계약으로 초기 화면 데이터를 내려준다.

## 목표 아키텍처

### 1. Sync Layer

XG5000와 직접 결합하지 않고 아래 입력원을 수집한다.

- `CSV sync`
  - 변수/설명 export 파일 감시
  - 변경 감지 시 자동 재파싱
- `Project snapshot sync`
  - `xgp`, `xgk`, `xgb`, `prj`, `txt`, `pdf` 같은 입력 파일의 메타데이터 스냅샷 유지
  - 파서가 불완전하면 `manual-review` 상태로 저장하되, 파일 버전과 변경 시각은 추적
- `Clipboard sync`
  - 사용자가 XG5000에서 복사한 LD/ST/에러 메시지를 감지해 보조앱 질문 초안으로 반영
- `PLC live sync`
  - PLC 상태, 모니터 값, 경보를 앱에서 직접 수집

### 2. UX Layer

- `항상 위 패널`
  - XG5000 옆에 붙여 쓰는 협소 폭 레이아웃
- `전역 단축키`
  - 질문창 열기
  - 현재 클립보드 내용으로 질문 초안 생성
  - 모니터 화면 빠른 토글
- `빠른 실행 패널`
  - 에러 코드 조회
  - 최근 프로젝트 스냅샷 보기
  - 최근 복사한 로직 기반 질문 실행

### 3. Data Layer

SQLite를 확장해 동기화 메타데이터를 보관한다.

- `project_snapshots`
  - 파일 경로, 해시, 수정 시각, 파서 상태, 요약
- `variable_snapshots`
  - 변수명, 디바이스, 타입, 설명, 소스 파일, 동기화 시각
- `sync_jobs`
  - 작업 종류, 상태, 마지막 실행, 결과 메시지
- `clipboard_captures`
  - 캡처 텍스트, 유형 추정, 생성 시각

## 구현 단계

## Phase 1. 파일 동기화 기반 마련

### 범위

- 설정 화면에 `동기화 폴더`와 `감시 파일 패턴` 등록
- 메인 프로세스에 파일 감시 서비스 추가
- CSV import를 수동 실행이 아니라 자동 동기화 작업으로 전환

### 구현 항목

- `main/services/file-sync-service.ts`
  - 폴더 watcher
  - debounce
  - 파일 해시 비교
- `main/parsers/variable-csv-parser.ts`
  - 변수/설명 CSV 파싱
- `main/parsers/project-snapshot-parser.ts`
  - xgp/prj 메타데이터 스냅샷
- IPC 추가
  - `sync.config.save`
  - `sync.status.read`
  - `sync.jobs.list`

### 완료 기준

- 사용자가 지정한 폴더에 CSV를 덮어쓰면 3초 이내에 앱 화면에 반영
- 최근 동기화 결과와 실패 원인이 설정 화면에서 확인 가능

## Phase 2. XG5000 보조앱 UX 고도화

### 범위

- 항상 위 모드
- 협소 폭 사이드 패널 모드
- 전역 단축키
- 클립보드 캡처 기반 질문 초안

### 구현 항목

- Electron main
  - `BrowserWindow.setAlwaysOnTop`
  - 글로벌 단축키 등록
- renderer
  - `Quick Ask` 오버레이
  - `Compact Mode` 레이아웃
  - 최근 클립보드 캡처 패널

### 완료 기준

- XG5000를 사용하는 동안 단축키 한 번으로 질문 패널 호출 가능
- 클립보드에 복사된 에러/로직 텍스트가 질문 초안에 자동 주입

## Phase 3. 프로젝트-질문 연결 강화

### 범위

- 최근 동기화된 프로젝트 스냅샷을 어시스턴트에 자동 주입
- 변수명/디바이스명 기반 질문 보조
- 에러 코드와 프로젝트 문맥 연결

### 구현 항목

- 어시스턴트 요청 구조 확장
  - `projectContext`
  - `recentClipboard`
  - `selectedVariable`
- KB 검색 전처리
  - 변수명과 디바이스명을 키워드에 추가
- UI
  - 프로젝트 브라우저에서 항목 선택 후 질문하기

### 완료 기준

- 사용자가 특정 변수나 프로젝트 파일을 선택한 뒤 질문하면, 응답 근거에 해당 문맥이 포함

## Phase 4. PLC 실기능 어댑터 전환 준비

### 범위

- 현재 시뮬레이션 어댑터를 실제 어댑터 인터페이스로 교체 가능한 상태까지 확장
- 읽기 중심 기능 우선

### 구현 항목

- `PlcAdapter` 인터페이스 세분화
  - `connect`
  - `readStatus`
  - `readDevices`
  - `subscribeMonitor`
- 오류 모델 정규화
  - 타임아웃
  - 권한 부족
  - 드라이버 미설치
  - 미지원 CPU

### 완료 기준

- 실 어댑터를 붙였을 때 renderer 수정 없이 main adapter만 교체 가능

## Phase 5. 운영 안정화

### 범위

- 자동 복구
- 세션 복원
- 동기화 실패 가시화
- 감사 로그 강화

### 구현 항목

- 앱 재시작 후 마지막 프로젝트/프로파일/동기화 폴더 복원
- watcher 실패 재시도 정책
- audit 로그에 `sync.*` 이벤트 추가

### 완료 기준

- 재시작 후 작업 중이던 화면과 동기화 설정이 복원
- 동기화 오류가 조용히 묻히지 않고 UI에 표시

## 우선순위

1. `Phase 1`
   파일 동기화가 없으면 보조앱이 로직 변경을 따라가지 못한다.
2. `Phase 2`
   사용성이 올라가야 XG5000 옆에서 실제로 쓸 수 있다.
3. `Phase 3`
   프로젝트 문맥이 붙어야 답변 품질이 올라간다.
4. `Phase 4`
   실제 PLC 연동은 인터페이스 검증 후 교체한다.
5. `Phase 5`
   운영 안정화는 기능 흐름이 고정된 뒤 진행한다.

## 리스크

- XG5000 export 형식이 현장마다 다를 수 있다.
- CSV 컬럼 순서나 인코딩 차이로 파서 예외가 발생할 수 있다.
- xgp 내부 구조는 공식 문서 없이 완전 해석이 어려울 수 있다.
- 파일 감시는 네트워크 드라이브 환경에서 이벤트 유실 가능성이 있다.

## 대응 방침

- 파서는 엄격하게 실패시키지 않고 `manual-review`로 폴백
- 인코딩은 UTF-8, EUC-KR, CP949 순으로 시도
- watcher 이벤트만 믿지 않고 `mtime + hash` 재검증
- 근거가 부족하면 UI와 답변 모두 `매뉴얼 확인 필요`로 안전 폴백
